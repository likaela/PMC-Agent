# 无企业历史的公开合成仓库准备

当前企业开发仓库保持私有。本地 commit、运行包与源码公开是三种不同授权，不自动互相继承。

## 推荐方式

经负责人确认后，在新的空目录创建独立仓库，只复制经过白名单审查的合成运行依赖、通用迁移、独立试用前端、合成JSON、依赖文件和公开说明。不要使用 fork、带 `.git` 的复制或保留企业历史的 clone 作为公开仓库起点。

1. 从固定交付 SHA 生成依赖清单，人工审查后导出源码，不包含 `.git`。
2. 后端只提供专用 trial API；检查其实际导入闭包，移除或参数化企业来源常量及私有映射。不得只复制整个项目后删除 raw。
3. 前端只包含独立 trial 入口和经编译白名单验证的共享模块；不复制企业 App、场景状态、路由、离线夹具、旧输出归档或调试资源。
4. 只保留完全合成的测试和示例；企业来源文件名、料号、校验值、实际数量和人员信息不进入公开源码。
5. 在不含企业原件、数据库、确认或私有环境变量的新目录安装依赖，运行测试、构建扫描、两账号和历史恢复验收。
6. 对全部待提交文件执行秘密、路径、业务标识和二进制内容检查；通过后由负责人授权新目录 `git init` 和首次提交。
7. 确认新的远端可见性后才决定 push。不要复用企业远端或擅自改变其可见性。

本轮只完成本地隔离构建和检查，不创建新远端、不改历史、不上传源码。

## 开放试用前

逐人分配独立账号，私下保存密码哈希与稳定代理密钥；安装校验过的代理和隧道工具。负责人另行批准后仅给本机认证代理建立 HTTPS 隧道，不对企业端口建立隧道。实际 HTTPS 登录、Host/Origin、刷新、限流及断线恢复必须在开放后另验收，不能用本机 HTTP 通过代替。
