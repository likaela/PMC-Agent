# 企业用户真实交互验收集

本轮只建立验收集，不新增企业能力，不修改路线、业务计算、数据库结构、前端或 Demo。
实施基线为现有 Phase 2 Orchestrator + 企业 Context Resolver。

## 1. 测试边界与运行方法

入口使用 FastAPI TestClient 向真实 `POST /api/v1/agent/query` 发送请求，携带
`persist_session=true`；后续请求携带 API 返回的 `session_id`。

实际链路：

```text
统一 API → 新建/恢复持久会话 → Planner → Context Resolver
        → 白名单 Registry → 既有 published-fact Tools / Services
        → Evidence → Response Generator → 保存问答与来源
```

只 mock DeepSeek 工厂及其结构化返回；不 mock Router、Parser、Resolver、Tool、业务
Service、Evidence 或会话 Repository。SQLite 使用每个用例独立的临时文件，按已有
migration 初始化，数据全部合成。未访问企业 `data/raw/` 或企业运行数据库，未改动
`demo_scenario_50_vs_100`。

LLM mock 是预先声明的意图与原文参数，不代表真实 DeepSeek 理解质量测评。Python
仍需验证该计划，并可能因规则优先、参数冲突或缺失而拒绝它。规则覆盖错误不会被
mock 绕过。最终意图、实际 Tool 名、完成步骤、结构化结果、持久化证据均参与断言。

```powershell
.\venv\Scripts\python.exe -m pytest tests/test_enterprise_user_acceptance.py -q -p no:cacheprovider
.\venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
git diff --check
```

新增文件包含 **75 个用例**：60 个角色自然语言问题、5 个异常场景、4 个 DeepSeek
故障/攻击场景、会话恢复、3 个权威事实缺失场景、来源保存与显式版本。每个测试均
执行真实 Agent API 链路；角色问题的数量与唯一性在夹具初始化时检查。

**验收未满足的断言保留为正常 FAIL，不使用 skip/xfail，不将泛化澄清伪装成业务成功。**
初次验收时全量测试在这些新增需求上返回非零退出码；下表及第 7/8 节保留初始
验收记录。最新契约和复验结果见第 9 节，不将历史结果误认为当前结果。

确定性预期：

- 理论最大整台数：75。现有公开契约的最大整台数是整数；物料 Decimal 保持字符串。
- 50 台：库存齐套，无采购需求；不触发 MOQ。

- 200 台：缺口 MAT-001 125、MAT-002 250；建议采购 130、250。
- MAT-002 因交期超过 7 天被既有规则列为高风险并优先排序。
- 这些结论只是事实库存分析和采购建议，不是生产放行、已下单或到货证明。

Context Resolver 应使用已发布快照的 UTC 日期补齐分析时点，使用唯一有效版本，
并保存来源。用户指定版本/日期优先；相对未来日期不自行换算成今天或快照日期。
采购开工日期未提供时必须询问。

## 7. 初次验收发现的问题（历史记录）

1. **P04/P20：原因追问重复调用生产计算。** 对话继承了参数，但没有直接使用历史
   Evidence 解释的路径。
2. **B01/B04/B05：采购语义被窄关键词误路由。** “需要采购”“采购多少钱”“采购
   邮件”进入 inbound；即使 mock 提供采购意图，规则优先也不允许改为采购规划。
3. **B10：MOQ 被当成显式料号。** 覆盖上下文中的 KQ-Z112，导致 BOM 查询不可用。
4. **B09/B15：成本只在 structured_data 中，未进入自然语言回答。** 计算正确。
5. **B05/B18：邮件草稿能力未接入。** 不新增此能力，不以采购列表冒充邮件草稿。
6. **B20：缺失供应商提示不具体。** 结构化 null/missing_fields 正确，回答泛化。
7. **W01/W02/W03/W04/W05/W15/W19/W20：风险/FIFO 入口未接入或缺少具体限制
   提示。** 原始库存/批次列表不能算诊断成功；底层规则存在不代表 Orchestrator 已调用。
8. **W14：有效期在批次事实中，但回答模板遗漏。**
9. **外部风险无 provider 时：只泛化询问意图，未明确说明无权威外部来源。**

这些是企业交互验收缺口，不是要求在本轮新增业务模块或改动计算层。

## 9. 体验修复及验收契约更新

体验修复后的中间结果为 69/75；剩余 6 项由用户确认更新以下契约：

- P13/P14 与 P04/P20 统一要求复用同一会话原始生产 Evidence，不执行新的 Tool。
  原请求必须真实执行 production_analysis；追问验证原 turn_id、查询参数、结果、
  来源及持久引用完全一致，限制物料断言保留，并拦截 BaseTool.invoke 防止重算。
- W01/W04/W19/W20 认可真实 published_inventory_risk_analysis 工具。白名单保持
  闭集，并验证本轮 operation=inventory_risk_analysis、data/provenance 与证据一致。
- inventory_risk_analysis 是规范注册名，inventory_risk 是兼容别名，两者复用
  同一个已存在、绑定当前会话 Store 的风险 Service，不改变风险算法。
- 企业风险工具仍不可在 Demo 调用，普通库存查询不会改为风险分析。

本轮专项复验：原验收 75/75、新增及此前体验测试 48/48 均通过（DeepSeek mock）。
未删除用例、未 skip 失败、未新增业务计算；完整结果记录见
`enterprise_agent_experience.md`。
